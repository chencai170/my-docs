# 关于本项目

## 项目目标

实现从 Markdown 文档到公开网站的自动化发布流程，即"推送代码 → 自动构建 → 自动部署 → 网页更新"的完整链路。

## 技术组成

| 工具 | 作用 |
| --- | --- |
| Markdown | 编写文档内容，专注于文字而非排版 |
| MkDocs Material | 将 Markdown 构建成美观的静态网站，提供导航、搜索等功能 |
| GitHub Actions | 云端自动化执行安装依赖、构建和部署操作 |
| GitHub Pages | 托管静态网站，提供公开可访问的 URL |

## 工作原理

整个流程可以分为三个层面：

1. **源码层**：存放在 `docs/` 目录下的 Markdown 文件，以及 `mkdocs.yml` 配置文件。这是我们真正需要维护和修改的内容。
2. **构建层**：MkDocs 读取源码，生成 `site/` 目录下的 HTML、CSS、JS 等静态文件。这一步在本地和 Actions 中都可以执行。
3. **部署层**：GitHub Actions 将构建产物上传，通过官方 Pages 机制发布到公网。用户访问的就是发布后的静态文件。

这种"分离"的好处是：我们只需要关心内容质量，构建和部署的繁琐工作全部交给自动化流程处理。

## 为什么选择 MkDocs Material

- 开箱即用的 Material Design 风格
- 内置搜索功能
- 支持代码高亮、表格、提示框等丰富语法
- 配置简单，一个 YAML 文件就能搞定导航和主题
- 社区活跃，插件生态丰富
