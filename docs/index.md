## 实践体会

这次实践让我对"文档即代码"有了更直观的理解。以前以为写文档就是随便写写 Markdown 文件，现在发现从源码到网站上线，中间其实有一套完整的工程化流程：本地编写 → 构建检查 → 自动部署 → 线上验证。

最有收获的地方是理解了 GitHub Actions 的工作机制。以前觉得 CI/CD 很神秘，做完这个项目才明白，其实就是在云端按照我们写好的步骤一步步执行：拉取代码、装依赖、跑构建、把产物上传、发布到 Pages。每一步都有日志可查，出错了也能定位到具体哪一行失败。

另外也体会到了静态网站的好处——内容和展示分离，只需要专心写 Markdown，样式和导航都由主题负责，非常省心。

自动部署验证：这是我第二次推送后更新的内容。

> ✨ **自动更新验证成功**：修改文档后推送到 main 分支，GitHub Actions 会自动构建并部署，几分钟后网站内容就会更新。这就是 CI/CD 的魅力——代码即文档，推送即发布。
